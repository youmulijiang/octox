# Octox 需求规格（requirements.md）

> 项目：Octox —— 聚合网络空间测绘引擎桌面客户端
> 技术栈：Rust + GPUI（Zed 的 GPU 加速 UI 框架）
> 方法：AI Spec 驱动开发（requirements → design → tasks → 实现 → 验证）

## 1. 愿景

Octox 提供单一桌面入口，将 FOFA、Hunter（鹰图）、Quake（360）三个测绘引擎的
查询、结果浏览与导出统一到一个界面中：一次输入查询语句，多引擎并发检索，
统一字段展示，支持分页与本地导出。

## 2. 合规声明（必须遵守）

- 仅限用户使用**自己合法注册**的平台账号与 API Key，并遵守各平台服务条款与配额。
- 查询与导出的数据仅用于**授权范围内**的安全研究 / 资产梳理。
- Octox 不内置任何账号、Key，不提供绕过配额或认证的能力。

## 3. 用户故事与验收标准（EARS）

### US1 引擎凭证配置
- **US1.1** 用户可在设置面板中分别填写 FOFA（email + key）、Hunter（api-key）、Quake（token）。
- **US1.2** 凭证保存后持久化到本地配置文件（`%APPDATA%/octox/config.json`）。
- **验收**
  - WHEN 用户填写凭证并点击「保存」THEN 配置文件被写入且界面提示已保存。
  - WHEN 应用重启 THEN 设置面板回显已保存的凭证。

### US2 多引擎并发查询
- **US2.1** 用户输入测绘查询语句（如 `app:weblogic`、`port:7001`），选择启用的引擎，点击「搜索」。
- **US2.2** 系统对每个启用引擎**并发**发起一次查询（每引擎独立线程池任务），不互相阻塞。
- **验收**
  - WHEN 查询语句为空 THEN 不发请求，状态栏提示「请输入查询语句」。
  - WHEN 某引擎未启用或未配置 Key THEN 跳过该引擎并在状态栏说明。
  - WHEN 某引擎返回错误（网络/配额/认证） THEN 其他引擎结果正常展示，该引擎错误显示在状态栏。
  - WHEN 新查询发起 THEN 旧查询的迟到结果被丢弃（代际防串扰）。

### US3 统一结果视图
- **US3.1** 三引擎结果映射到统一资产模型（引擎/主机/IP/端口/协议/标题/组件/组织/位置/更新时间），按引擎着色。
- **US3.2** 用户可点击结果行选中，状态栏/详情区显示完整字段。
- **验收** WHEN 引擎返回非空数据 THEN 表格按统一列渲染，空字段显示 `-`。

### US4 分页
- **US4.1** 支持上一页/下一页，每页条数可选 10/20/50/100。
- **US4.2** 分页语义由各引擎客户端归一化（FOFA page 1 起；Hunter search.start 页码 1 起；Quake start = (page-1)*size 偏移 0 起）。
- **验收** WHEN 翻页 THEN 以新页码重新发起全部启用引擎的查询。

### US5 导出
- **US5.1** 用户可将当前缓冲区全部结果导出为 CSV（UTF-8 with BOM，Excel 友好）与 JSON。
- **验收** WHEN 无结果时导出 THEN 状态栏提示且不生成文件；WHEN 导出成功 THEN 状态栏显示文件绝对路径。

### US6 状态与配额反馈
- **US6.1** 状态栏常驻显示：加载中 / 完成（各引擎条数）/ 错误 / 各引擎剩余配额（平台返回时）。
- **US6.2** 查询期间界面保持响应（网络在后台执行，主线程不阻塞）。

### US7 冒烟自检
- **US7.1** `octox --smoke` 启动窗口并在 3 秒后自动退出，用于无交互环境的启动自检。

## 4. 非目标（v1 明确不做）

- 引擎查询语法互译（各引擎使用各自原生语法）。
- 结果去重聚合、批量导出全部页（仅导出当前缓冲区）。
- 代理配置、结果缓存、历史记录。
- 中文 IME 输入法完整接入（v1 输入框仅支持直接键入 ASCII 字符与剪贴板粘贴；
  中文语句请粘贴输入，IME 集成列入 v1.5）。
- 自动更新、多语言。

## 5. 关键约束

- Windows 10/11 优先目标平台（开发环境），GPUI DirectX 渲染。
- 每次引擎请求超时 30s；每页条数上限 100（尊重三家平台的单页限制）。
- 密钥文件权限仅为当前用户可读（尽力而为，文档中说明路径）。
